# 教务退款与优惠体系 PRD

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 文档名称 | 教务退款与优惠体系 PRD |
| 产品范围 | 线上课返利、现金支付优惠、优惠活动、个人折扣、运营退课、财务特殊退课、财务特殊退费、财务退款审批 |
| 目标读者 | 产品、设计、前端、后端、测试、运营、财务 |
| 核心目标 | 建立统一的订单优惠和退款计算基础，区分运营常规退课与财务特殊退款，并通过多人审批保证退款准确性 |

---

## 2. 背景与产品目标

当前系统中的优惠、退课、退款和审批逻辑分散在不同业务页面中，容易出现以下问题：

- 同一笔订单的优惠金额、现金优惠和课次退款金额口径不一致。
- 运营退课、财务特殊退课和财务特殊退费的适用范围不清晰。
- 已下课、未上课、直播课、高端班等课次状态对退款结果的影响不透明。
- 财务填写了退款申请后，缺少提交人和审核人分离的审批控制。
- 退款金额只展示结果，财务无法快速理解金额的计算来源。

本产品需要建立一套完整的规则链路：

```text
系统底层配置
    ↓
订单与课次数据
    ↓
运营常规退课 / 财务特殊退课 / 财务特殊退费
    ↓
退款金额计算
    ↓
财务多人审批
    ↓
审批通过后执行真实退款并更新订单、课次状态
```

### 2.1 产品目标

1. 将所有优惠规则沉淀为系统级配置。
2. 建立订单级和课次级的完整金额数据模型。
3. 明确运营退课与财务特殊退款的边界。
4. 对不同退款场景提供可解释的金额计算明细。
5. 财务退款申请必须经过其他财务人员审核，提交人与审核人不能为同一人。
6. 只有审批全部通过后，系统才真正执行退款。

### 2.2 非目标

本期不涉及：

- 实际支付渠道接口的具体对接方案。
- 银行、第三方支付平台的清算规则。
- 复杂的组织架构权限管理后台。
- 审批流程编排器的通用开发，只需要支持按实际情况配置审核人数。

## 3. 角色定义

| 角色 | 主要职责 |
| --- | --- |
| 运营人员 | 处理符合常规规则的退课，查看订单和课次状态，发起允许范围内的退课操作 |
| 财务提交人 | 处理无法由运营直接完成的特殊退课和特殊退费，填写退款方式、金额、说明并提交审批 |
| 财务审核人 | 审核其他财务人员提交的退款申请，核对订单、课次、金额和退款账户，决定通过或驳回 |
| 财务负责人/管理员 | 配置需要几名审核人，维护审核人范围和审批流程 |
| 运营主管 | 维护优惠活动、个人折扣等系统级配置，并查看业务数据 |
| 系统 | 根据配置计算金额、限制操作、流转审批、执行退款和更新数据 |

### 3.1 提交人与审核人隔离

财务A提交的退款申请，不能由财务A本人审核。

系统至少需要满足：

- 当前登录人是申请提交人时，不显示该申请的可审核操作。
- 审核人必须是其他具备财务审核权限的人员。
- 如果没有可用的其他审核人，提交时提示无法提交，并说明需要配置其他财务审核人。
- 审核完成后记录审核人、审核时间和审批结果。

## 4. 系统级底层配置

以下四类配置属于整个系统的底层配置，不是某一笔订单的临时配置。订单在创建或优惠生效时，需要保存当时实际使用的配置快照，避免后续修改配置影响历史订单。

### 4.1 线上课返利配置

线上课返利用于定义直播课在满足条件后可以返还给学员的金额。

#### 4.1.1 核心规则

- 只有直播课可以参与线上课返利。
- 直播课必须下课后才可以返利。
- 线下课不能参与线上课返利。
- 已返利金额需要记录在课次明细中。
- 剩余可返利金额 = 当前课次可返利金额 - 已返利金额。
- 线上课返利是否可以与优惠活动叠加，由优惠活动的“允许叠加线上课返利”开关控制；不允许叠加时，该订单不再支持线上课返利。

#### 4.1.2 建议配置字段

| 字段 | 说明 |
| --- | --- |
| 返利规则名称 | 便于运营识别规则 |
| 适用课程/班级 | 指定哪些课程或班级属于返利范围 |
| 单课次返利金额 | 每个直播课课次可返利的金额 |
| 返利条件 | 例如必须下课、订单必须使用指定优惠等 |
| 是否允许与优惠活动叠加 | 控制返利与优惠活动是否同时生效 |
| 生效时间 | 规则开始和结束时间 |
| 状态 | 未开始、进行中、已停用、已结束 |

### 4.2 现金支付优惠配置

现金支付优惠是订单层面的底层优惠。它与优惠活动、个人折扣优惠分开记录，但参与订单总优惠和退款计算。

#### 4.2.1 核心规则

- 现金优惠需要分摊到该订单购买的全部课次。
- 现金优惠不应被错误地全部计入某一个课次。
- 分摊金额精确到分。
- 前面的课次向下取分，最后一个课次补齐差额。
- 订单最终优惠金额应等于活动/折扣优惠金额与现金优惠金额之和。

#### 4.2.2 分摊示例

订单共有 15 个课次，现金优惠 50 元：

```text
前 14 个课次：floor(50 / 15 * 100) / 100 = 3.33 元
第 15 个课次：50 - 14 × 3.33 = 3.38 元
```

### 4.3 优惠活动配置

优惠活动是面向一批课程、班级或学员的系统级营销规则。

#### 4.3.1 活动状态

活动状态包括：

- 未开始：当前时间早于活动开始时间。
- 进行中：当前时间位于活动生效区间，且没有被暂停。
- 已暂停：活动被人工暂停，且未到结束时间。
- 已结束：当前时间晚于结束时间。

#### 4.3.2 活动规则适用人群

活动可以分别为以下人群设置规则：

- 在读学员
- 老学员
- 新学员
- 指定范围学员

#### 4.3.3 活动优惠类型

每类人群可以配置不同优惠类型：

- 特价
- 折扣
- 满减
- 课次优惠
- 无优惠

#### 4.3.4 活动限制条件

活动必须配置以下限制条件：

```text
允许退课后重复使用：默认允许
允许叠加线上课返利：默认不允许
```

“退课后是否可以重复使用”控制学员退课后是否仍可再次参与活动。

“允许叠加线上课返利”控制直播课返利是否可以与该活动同时计算。

#### 4.3.5 活动退费规则

活动需要配置退费规则：

1. 按折扣价退费
   - 按用户实际支付的优惠后金额，结合退课课次占比计算退款。
2. 按原价退费
   - 按原价计算已课耗金额，扣除已退款金额后退还剩余金额。

#### 4.3.6 活动配置页面要求

活动列表支持：

- 活动状态下拉多选：未开始、进行中、已暂停、已结束。
- 年度下拉多选：过去 5 年、当前年、未来 1 年。
- 活动名称模糊搜索。
- 开始时间 - 结束时间筛选。

默认筛选：

- 活动状态选中未开始、进行中。
- 年度选中当前年。

活动列表字段：

| 字段 | 说明 |
| --- | --- |
| 活动名称 | 固定列，活动的业务名称 |
| 活动状态 | 标签显示四种状态 |
| 活动内容 | 展示各人群使用的优惠规则 |
| 限制条件 | 展示退课后是否可重复使用、是否叠加线上课返利 |
| 参与班级数 | 关联的课程/班级数量 |
| 生效时间 | 开始时间至结束时间 |
| 关联订单 | 已使用该活动的订单统计 |
| 活动渠道 | 系统后台、app、服务号、小程序、官网 |
| 所属年份 | 活动所属年度 |
| 退费规则 | 按折扣价退费或按原价退费 |
| 操作 | 修改、停用/启用、查看日志 |

已结束活动不显示停用/启用操作。停用操作使用红色文字，并必须二次确认。

新增/编辑活动使用右侧抽屉：

- 活动名称必填。
- 活动生效时间放在活动名称下方。
- 开始、结束时间支持年月日时分秒。
- 活动课程/班级支持按课程或班级多选。
- 活动渠道下方展示退费规则。
- 抽屉支持点击遮罩关闭。
- 页面右上角固定展示“新增优惠活动”和“批量操作”。

### 4.4 个人折扣配置

个人折扣用于为指定学员配置专属折扣，属于系统级折扣规则和学员级应用记录的组合配置。

#### 4.4.1 折扣规则

预置折扣规则只有三类：

1. 内部员工子女（含亲兄弟姐妹），默认折扣 20%。
2. 比心计划，默认折扣为空。
3. 特殊关系，默认折扣为空。

默认折扣为空表示该规则只定义名称和业务归类，不定义固定比例。给学员申请折扣时必须单独填写折扣比例。

折扣规则配置列表字段：

| 字段 | 说明 |
| --- | --- |
| 规则名称 | 折扣规则名称 |
| 默认折扣（%） | 例如 20、30、40；为空表示需要在学员申请时填写 |
| 学员数量 | 当前使用该规则的学员数量，可点击跳转学员明细 |
| 状态 | 启用中、已停用 |
| 备注说明 | 规则的业务解释 |
| 退费规则 | 按原价退费、按折扣价退费 |
| 操作 | 启用、停用、编辑 |

学员数量点击后：

- 打开学员折扣明细页面。
- 默认选中当前折扣规则。
- 折扣状态切换为全选。

新建折扣规则：

- 点击“新建折扣规则”原地打开右侧抽屉。
- 默认折扣可以不填。
- 默认折扣后展示：

```text
如果此处不填写，可以在帮学员申请折扣时填写
```

#### 4.4.2 学员折扣明细

页面导航显示“学员折扣明细”。页面右侧按顺序展示：

1. 新增学员折扣，按钮高亮并带审批标签。
2. 折扣规则配置，使用配置图标。

学员折扣明细支持：

- 按姓名搜索。
- 按学号搜索。
- 按状态多选。
- 按折扣规则单选筛选。

状态包括：

- 未开始
- 启用中
- 已停用
- 已过期
- 审批中
- 审批未通过

默认选中“审批中”。

表格字段：

| 字段 | 说明 |
| --- | --- |
| 姓名 | 学员姓名 |
| 学号 | 学员唯一学号 |
| 手机号 | 中间 4 位脱敏 |
| 折扣状态 | 六种状态标签 |
| 优惠规则 | 关联的系统折扣规则，可点击查看规则配置 |
| 折扣比例（%） | 例如 20%、30% |
| 生效时间 | 开始时间和结束时间，支持年月日时分秒 |
| 适用范围 | 选择的课程和班级 |
| 备注信息 | 申请备注 |
| 审批编号 | 可点击查看审批明细 |
| 操作 | 启用/停用、日志 |

只有“已停用”且当前日期位于生效时间范围内的记录才允许启用。

#### 4.4.3 新增学员折扣

点击“新增学员折扣”打开右侧抽屉，先选择：

- 手动选择学员
- 批量导入学员

批量导入只改变学员选择方式，其他字段与手动选择一致。

手动选择学员支持姓名、学号、手机号搜索。

折扣规则：

- 必选。
- 默认不选中任何规则。
- 选中后回显该规则默认折扣。
- 默认折扣为空时，折扣比例保持空白，等待用户填写。
- 折扣比例允许手动修改。

折扣比例标题右侧展示：

```text
默认取折扣规则的比例，支持手动修改
```

折扣比例使用金黄色高亮，百分号放在输入框内部右侧。

适用范围：

- 文案为“适用课程或班级范围”。
- 单独占一行。
- 支持课程和班级选择。
- 点击后打开课程/班级选择弹窗。
- 不再单独展示课程和班级两个字段。

时间：

- 开始时间和结束时间位于同一行。
- 均支持年月日时分秒。

审批人信息位于抽屉底部：

```text
连续多级上级审批
洪重萍 --> 龙芳

一级部门主管会签
陈茹 和 刘帅

财务主管审批
财务主管
```

提交按钮为“提交审批”。

### 4.5 分摊金额计算说明

- 分摊金额精确到分。
- 前面的课次向下取分，最后一个课次补齐差额。

订单共有 15 个课次、现金优惠 50 元时：

```text
前 14 个课次：floor(50 / 15 × 100) / 100 = 3.33 元
第 15 个课次：50 - 14 × 3.33 = 3.38 元
```

### 5.2 课次明细字段总表

每个订单必须保存一组课次明细。课次明细是退款计算的最小单位。

| 字段 | 类型/示例 | 业务含义 | 使用场景与规则 |
| --- | --- | --- | --- |
| 课次编号 | 1、2、3 | 课次在订单中的序号 | 用于定位具体课次 |

| 活动/折扣优惠金额 | ¥105.00 | 活动或个人折扣分摊到本课次的金额 | 与现金优惠分开存储 |
| 现金优惠金额 | ¥3.33 | 现金优惠分摊到本课次的金额 | 前面课次向下取分，最后一个课次补差额 |

| 已返利金额 | ¥15.00 | 本课次线上返利已退金额 | 计算剩余可返利金额 |
| 剩余可退款金额 | ¥66.67 | 本课次当前还能退款的金额 | 通用退款和高端班退款使用 |
| 剩余可返利金额 | ¥0.00 | 本课次当前还能返利的金额 | 线上课返利使用 |
| 本次是否退款 | 是/否 | 当前申请是否包含该课次 | 课次高亮和金额合计 |
| 本次退款分摊金额 | ¥66.66 | 本次申请分摊到该课次的金额 | 自定义退款金额使用 |

### 5.3 订单金额关系

订单级金额与课次级金额的关系：

```text
课程总价 = 所有课次原价之和
订单活动/折扣优惠金额 = 所有课次活动/折扣优惠金额之和
订单现金优惠金额 = 所有课次现金优惠金额之和
订单优惠总额 = 活动/折扣优惠金额 + 现金优惠金额
实付金额 = 课程总价 - 订单优惠总额
订单已退款金额 = 所有课次已退金额之和
```

历史订单必须保存优惠规则快照。即使后续优惠活动或个人折扣规则被修改，历史订单退款仍按订单当时的快照计算。

## 6. 角色场景一：运营操作退课

### 6.1 角色与目标

角色：运营人员。

目标：在不需要财务特殊审批的情况下，按照系统允许的常规规则办理退课。

### 6.2 用户故事

> 作为运营人员，我希望选择学员要退的课次，系统根据订单优惠和课次状态自动计算可退金额，从而直接完成符合常规规则的退课，避免人工计算错误。

### 6.3 业务流程

```text
运营打开订单
  ↓
查看订单总价、优惠、现金优惠、实付金额和课次明细
  ↓
选择允许退课的课次
  ↓
系统计算本次可退款金额
  ↓
运营确认退款方式和办理校区
  ↓
系统执行常规退款
  ↓
更新订单已退款金额和课次状态
```

### 6.4 系统规则

- 运营只能选择系统判断为可退的课次。
- 运营可选课次必须是“未上课且未退课”的课次。
- 剩余可退课次必须一起选择，不支持只选择其中一节课。
- 未达到特殊退款条件的课次不能通过运营常规流程强制退款。
- 选择课次后，金额随选择实时重新计算。
- 课次明细中展示原价、优惠金额、课耗金额、已退金额和剩余可退款金额。
- 退款完成后，订单已退款金额增加，相关课次已退金额增加。
- 已完成退款的课次状态更新为已退课。
- 运营不支持切换退款方式。

### 6.5 运营页面要求

课次选择：

- 支持多选。
- 当前选择课次高亮。
- 课次状态清晰展示。

本次退款金额区域展示：

- 本次退款金额。
- 退款方式。
- 办理校区。
- 退款金额问号。

点击退款金额问号打开“本次退款金额明细”，需要展示可读的计算公式，而不是只展示最终金额。

## 7. 角色场景二：财务特殊退课

### 7.1 角色与目标

角色：财务提交人。

目标：处理运营常规退课无法覆盖、但业务上确实需要为学员办理退款的特殊退课。

### 7.2 用户故事：学员已经下课但没有去上课

> 学员已经被系统标记为已下课，但实际没有参加该课次。家长申请退掉这一次课。运营流程无法直接把已下课课次作为普通未消耗课次处理，因此财务人员需要发起“已下课课次退课”的特殊退课申请。

### 7.3 财务特殊退课场景

#### 场景 A：已下课课次退课

适用情况：

- 课次状态是已下课。
- 学员实际未参加课程或存在需要人工核实的特殊原因。
- 财务决定按照特殊规则为该课次办理退款。

用户故事：

> 作为财务提交人，我希望选择已经下课但确实需要退款的课次，填写原因并提交审批，审批通过后系统才更新课次状态并执行退款。

系统规则：

- 可以选择已下课课次。
- 选择后提示：

```text
已下课次操作退款后，课次状态将更新为已退课
```

- 本次退款金额按课次实际支付金额计算。
- 课次明细中标记“本次退款”。
- 审批通过前，不更新课次为已退课，不增加订单已退款金额。
- 审批通过后，课次状态更新为已退课。

#### 场景 B：单次课退课

适用情况：

- 学员只申请退掉单次或少量课次。
- 课次可能已经下课，也可能属于需要人工处理的特殊课次。

用户故事：

> 作为财务提交人，我希望为学员选择指定的一次或多次课次，系统按照所选课次和实际支付金额计算退款，并提交给其他财务审核。

系统规则：

- 支持选择指定课次。
- 所选课次高亮，并显示“本次退款”。
- 退款金额为所选课次可退款金额之和。
- 不允许退款超过课次剩余可退款金额。

### 7.4 财务特殊退课申请字段

| 字段 | 规则 |
| --- | --- |
| 申请类型 | 固定为特殊退课 |
| 退课场景 | 单次课退课、已下课课次退课 |
| 选择课次 | 支持多选，已下课课次可在特殊场景下选择 |
| 退课原因 | 必填或按场景要求填写 |
| 申请说明 | 记录人工核实过程和补充说明 |
| 退款金额 | 系统自动计算，不允许超过最大可退金额 |
| 退款方式 | 根据订单付款方式限制可选项 |
| 办理校区 | 非必填 |
| 关联班级 | 从订单带出 |
| 关联订单编号 | 从订单带出 |

## 8. 角色场景三：财务特殊退费

### 8.1 角色与目标

角色：财务提交人。

目标：处理不属于普通退课，而是因为返利、升班、活动变更或人工约定需要退款的场景。

### 8.2 场景 A：线上课返利

用户故事：

> 学员购买了包含直播课的订单，部分直播课已经下课并符合返利条件。财务需要按照已下课直播课数量计算返利金额，并提交给其他财务人员审核。

系统规则：

- 直播课标签显示“直播课”，颜色为 `#C9632E`。
- 非直播课标签显示“线下课”。
- 只有直播课可以返利。
- 直播课必须下课后才可返利。
- 已经返利的金额需要从剩余可返利金额中扣除。
- 当前可返利课次所在行高亮。
- 优惠活动配置为不允许叠加线上课返利时，该订单不再支持线上课返利。

金额计算：

```text
可返利直播课数量 × 单课次返利金额 = 本次退款金额
```

弹窗需要展示：

- 当前订单使用的优惠券信息，有则展示，无则不展示。
- 本次退款计算方法。
- 课次状态、原价、优惠金额、课耗金额、已返利金额、剩余可返利金额。

### 8.3 场景 B：高端班半价

用户故事：

> 学员原先购买普通班，后续升班到高端班。财务需要只对符合条件的高端班课次办理半价退款，且未下课的高端班课次不能提前退款。

系统规则：

- 高端班课次显示“高端班”，颜色为 `#C9632E`。
- 非高端班课次显示“非高端班”。
- 当前可退款课次高亮。
- 升班至高端班时，只有已下课的高端班课次可退款。
- 如果所有课次都是高端班，视为直接购买高端班。
- 如果只有部分课次是高端班，视为升班至高端班。
- 第 6-15 课次未下课时，不应被选中或计入退款。

金额计算：

```text
符合条件的高端班课次数量 × 每课次可退金额 = 本次退款金额
```

弹窗需要展示：

- 当前订单使用的优惠券信息，有则展示，无则不展示。
- 本次退款计算方法。
- 高端班/非高端班标签。
- 课次状态和剩余可退金额。

### 8.4 场景 C：优惠活动退差价

用户故事：

> 学员原订单已经使用优惠活动支付，后续活动规则发生变化或学员符合更低价活动。财务需要展示原优惠和更换后优惠，并退还两种优惠之间的差额。

系统规则：

- 弹窗展示原优惠信息；原订单无优惠时展示“无优惠”。
- 展示更换后的优惠信息。
- 不能只展示最终差价，必须展示差价的来源。
- 需要展示原优惠金额、现优惠金额、每课次可退差价和最终退款金额。

金额计算：

```text
符合条件课次数量 × 每课次优惠差价 = 本次退款金额
```

### 8.5 场景 D：自定义退费金额

用户故事：

> 学员因为特殊情况申请退款，财务根据沟通结果输入一个约定的退款金额。系统需要校验该金额不超过最大可退款金额，并将本次金额分摊到订单课次。

系统规则：

- 自定义退款金额不能大于最大可退款金额。
- 最大可退款金额按订单全量字段计算。
- 本次退款金额分摊到指定参与分摊的课次。
- 前面的课次向下取分，最后一个课次补齐差额。
- 本次退款前已退金额和本次退款后已退金额必须分别展示。

待产品确认：如果订单全部课次都已上完，但家长仍申请部分退款，课耗金额是否按全部课程总价扣除，还是允许人工豁免并设置特殊可退上限。

金额计算：

```text
最大可退款金额
= 课程总价
- 活动/折扣优惠金额
- 现金优惠金额
- 课耗金额
- 已退款金额
```

### 8.6 财务特殊退费通用字段

| 字段 | 规则 |
| --- | --- |
| 申请类型 | 固定为特殊退费 |
| 退费场景 | 线上课返利、高端班半价、优惠活动退差价、自定义退费金额 |
| 退款金额 | 按场景计算，不能超过可退上限 |
| 退款方式 | 根据付款方式限制 |
| 申请说明 | 必填，说明特殊处理原因 |
| 办理校区 | 必填 |
| 关联班级 | 从订单带出 |
| 关联订单编号 | 从订单带出 |
| 申请人 | 当前财务登录人 |
| 申请时间 | 系统生成 |

## 9. 退款方式与执行规则

### 9.1 退款方式

支持的退款方式：

- 原路退回
- 现金退款
- 银行转账

### 9.2 现金支付订单

如果订单付款方式是现金支付：

- 默认退款方式为现金退款。
- 不允许选择原路退回。
- 可以切换为银行转账。

### 9.3 银行转账

银行转账必须采集：

- 户名
- 卡号，完整展示，不脱敏
- 开户行

审批列表和审批详情中都要展示完整账户信息，供审核人核对。

### 9.4 审批通过前不得执行退款

提交审批只是生成退款申请，不是真正退款。

审批通过前：

- 不调用退款渠道。
- 不增加订单已退款金额。
- 不更新课次为已退课。
- 不扣减剩余可退款金额。

全部审批通过后：

- 执行对应退款方式。
- 更新订单已退款金额。
- 更新课次已退金额或已返利金额。
- 符合条件的课次更新为已退课。
- 记录退款执行时间和执行结果。

## 10. 财务退款审批

### 10.1 为什么需要审批

财务特殊退课和财务特殊退费通常属于运营常规规则之外的人工判断，金额和课次状态存在较高风险。因此：

- 财务提交人负责说明业务原因和填写申请。
- 其他财务人员负责复核订单、课次、优惠、金额和退款账户。
- 提交人和审核人不能是同一个人。
- 只有审批通过后才真正退款。

### 10.2 审批人数配置

审核人数根据实际管理要求配置，可以是 1 人，也可以是 N 人。

系统配置项：

- 需要审核人数 `N`。
- 可审核财务人员范围。
- 审核顺序：依次审核或并行会签。
- 提交人是否自动排除：必须开启。

默认规则：

- 至少需要 1 名其他财务人员审核。
- 当前申请人不能成为自己的审核人。
- N 名审核人全部通过后，审批状态才变为已完成。
- 任意一名审核人驳回，审批状态变为已驳回，不执行退款。

### 10.3 审批流程

```text
财务A打开订单
  ↓
选择特殊退课或特殊退费场景
  ↓
系统计算退款金额并展示金额明细
  ↓
财务A填写退款方式、办理校区、申请说明
  ↓
财务A提交审批
  ↓
系统校验申请人和审核人不能相同
  ↓
按照配置分配 1 名或 N 名其他财务审核人
  ↓
财务B / 财务C ... 审核
  ↓
全部审核通过？
  ├─ 否：任一人驳回，填写驳回原因，流程结束
  └─ 是：执行退款，更新订单和课次状态
```

页面直接展示三个 Tab：

- 待处理

筛选和搜索：

- 退课/退费场景
- 退款方式

- 申请编号独立搜索
- 学员信息独立搜索

列表为宽表格，不使用卡片布局。

字段顺序：

| --- | --- |
| 提交申请 | 提交人、提交时间、已提交 |
| 第 1 审核人 | 审核人、审核时间、待处理/已通过/已驳回 |
| 第 2 至 N 审核人 | 按配置展示对应审核节点 |
| 退款执行 | 审批全部通过后展示执行时间和执行结果 |

### 10.6 通过操作

点击“通过”必须弹出二次确认。

原路退回提示：

```text
当前为原路退款，确认后将立即将¥xxx原路退回给家长。
```

现金退款提示：

```text
当前为现金退款，请确认已通过现金方式为家长办理了¥xxx的退款后再确认。
```

银行转账提示：

```text
请确认已向家长提供的账户（户名、卡号、开户行）转账¥xxx。
```

确认按钮：

```text
我已确认
```

### 10.7 驳回操作

点击“驳回”：

- 打开填写驳回原因弹窗。
- 驳回原因必填。
- 确认驳回后记录驳回人、驳回时间、驳回原因。
- 状态变为已驳回。
- 不执行退款。
- 不更新课次已退金额和课次状态。

## 11. 金额明细统一展示规范

所有退款入口的问号都必须打开同一套可解释的金额明细组件，但根据业务场景展示不同内容。

### 11.1 通用结构

1. 弹窗标题：本次退款金额明细。
2. 优惠信息区：展示订单实际使用的优惠快照。
3. 本次退款计算区：用公式说明金额来源。
4. 课次明细表：展示每个课次的金额组成。
5. 合计行：所有课次金额合计必须等于本次退款金额。

### 11.2 场景公式

| 场景 | 计算公式 |
| --- | --- |
| 已下课课次退课 | 所选已下课课次数量 × 单课次实际支付金额 |
| 单次课退课 | 所选课次可退款金额之和 |
| 线上课返利 | 符合条件的直播课数量 × 单课次返利金额 |
| 高端班半价 | 符合条件的高端班课次数量 × 每课次可退金额 |
| 优惠活动退差价 | 符合条件课次数量 × 每课次优惠差价 |
| 自定义退费金额 | 申请人填写金额，按课次分摊，并校验不超过最大可退款金额 |

## 12. 异常与边界规则

### 12.1 金额边界

- 退款金额不能小于 0。
- 退款金额不能超过最大可退款金额。
- 退款后订单已退款金额不能超过实付金额。
- 退款后课次已退金额不能超过该课次可退金额。
- 同一订单存在未完成退款申请时，需要防止重复提交或锁定可退款金额。
- 同一个订单同时只能存在 1 个退款审批中的申请；存在审批中的申请时，不允许再次发起退款。

### 12.2 时间边界

- 活动开始时间不能晚于结束时间。
- 折扣生效开始时间不能晚于结束时间。
- 当前日期不在个人折扣生效范围内时，不允许启用已停用记录。
- 未到生效时间的规则不能进入启用中状态。

### 12.3 审批边界

- 申请人不能审核自己的申请。
- 审核人数不足时不能提交审批。
- 任意审核人驳回后，不允许继续执行退款。
- 全部审核通过后才能执行退款。
- 退款执行失败时，审批状态不能伪装为已完成，需要记录执行失败原因。

## 14. 验收标准

### 14.1 系统配置

- 线上课返利、现金支付优惠、优惠活动、个人折扣都能独立配置。
- 历史订单使用配置快照，不受后续规则修改影响。

### 14.2 订单数据

- 订单字段表中的字段均可追溯。
- 订单级金额和课次级金额可以相互核对。
- 活动/折扣优惠金额与现金优惠金额分开保存。
- 课次优惠金额等于活动/折扣优惠金额加现金优惠金额。

### 14.3 退款场景

- 运营常规退课和财务特殊退款入口区分明确。
- 已下课但未实际参加的课次可以通过财务特殊退课处理。
- 未下课课次不能参与高端班半价退款。
- 直播课返利必须满足下课条件。
- 优惠活动退差价展示原优惠和更换后优惠。
- 自定义金额不能超过最大可退款金额。
- 所有金额明细可解释、可复核。

### 14.4 审批流程

- 财务A可以提交特殊退课/特殊退费申请。
- 财务A不能审核自己提交的申请。
- 审核人数支持 1 人或 N 人配置。
- 审核未完成前不会真正退款。
- 全部审核通过后才执行退款和更新订单数据。
- 任一审核人驳回后记录原因且不执行退款。

### 14.5 页面交互

- 申请编号点击打开右侧审批详情抽屉。
- 退款金额问号打开金额计算明细。
- 通过操作有二次确认。
- 驳回操作必须填写原因。
- 停用操作有二次确认。
- 银行卡号在财务审批场景完整展示。
- 审批列表为宽表格，申请编号和学员信息固定。
